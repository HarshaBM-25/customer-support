# Sampling Notes — Golden Evaluation Set

## Overview

- **Total examples:** 200
- **Source:** `data/processed/amazon_threads_clean.jsonl` (5,000 AmazonHelp threads)
- **Output files:**
  - `data/eval/golden_set_human.jsonl` — JSONL scaffold for human review
  - `data/eval/golden_set_human_review.csv` — CSV version for spreadsheet editing

## How the 200 examples were sampled

The golden set was built by stratified sampling across 8 intent categories
(25 examples per intent), using keyword heuristics to approximate intent
for stratification purposes only.

1. From 5,000 cleaned AmazonHelp threads, the first customer-initiated
   message was extracted from each thread.
2. A keyword-based heuristic assigned an approximate intent to each message
   (used only for balancing the sample, NOT as ground truth).
3. 25 examples were randomly sampled from each of the 8 intent categories
   (seed=42), producing 200 total examples.
4. The sample was shuffled and re-indexed.

## Pre-labeler suggestions

Each example includes `suggested_intent` and `suggested_route` fields
generated by a keyword/regex heuristic in `src/create_human_review.py`.

**These suggestions are NOT ground truth.** They exist only to speed up
human review. The human reviewer must independently verify or override
each suggestion.

## Human review process

The human reviewer fills in three fields for each example:

1. **`human_intent`** — the correct intent from the 8-class taxonomy
2. **`human_route`** — `AUTO` or `ESCALATE`
3. **`human_route_reason`** — brief justification for the routing decision

After reviewing, `human_reviewed` is set to `true`.

Only examples where `human_reviewed = true` are used as evaluation
ground truth.

## Columns in the review file

| Column | Description |
| :--- | :--- |
| `id` | Unique example ID (1–200) |
| `thread_id` | Source conversation thread ID |
| `raw_text` | Original uncleaned customer message |
| `cleaned_text` | Normalized and PII-scrubbed message |
| `conversation_context` | First 6 turns of the conversation for context |
| `amazon_actual_reply` | Amazon's original historical reply |
| `num_turns` | Total turns in the conversation thread |
| `suggested_intent` | Keyword heuristic suggestion (NOT ground truth) |
| `suggested_route` | Keyword heuristic suggestion (NOT ground truth) |
| `suggested_route_reason` | Reason for the suggested route |
| `human_intent` | **Human-assigned intent (ground truth)** |
| `human_route` | **Human-assigned route (ground truth)** |
| `human_route_reason` | **Human justification** |
| `human_reviewed` | **Review completion flag** |

## Held-out Evaluation Split & Leakage Prevention

To ensure strict zero-leakage evaluation:
1. The 200 evaluation threads are strictly excluded from the retrieval corpus.
2. A separate held-out knowledge base of 4,787 resolved customer support cases (`data/processed/knowledge_corpus.jsonl`) is indexed for RAG.
3. `CaseRetrievalEngine` enforces exclusion by explicitly tracking `exclude_thread_ids`, guaranteeing that no evaluation thread can retrieve itself or its historical ground-truth resolution.
